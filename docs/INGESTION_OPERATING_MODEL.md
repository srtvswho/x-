# 采集与解读运行方式

目标：新增账号、历史补采、回复/引用链、图片等场景共享同一套任务与证据，不再复制一条临时工作流。现有实现已具有缓存、覆盖证明、累计预算、缺失解读队列、离线发布；长期统一调度仍是待接入项。

| 层 | 必须保存的状态 | 失败时行为 | 现有落点 |
| --- | --- | --- | --- |
| 任务 | 场景、账号、时间区间、数据类型、费用上限、授权期限 | 未配置不收费 | 有限采集 state.config；AI 固定 campaign |
| 采集适配器 | 原始响应、分页游标、请求预留费用、请求状态 | 不确定结果先核对，不能盲重发 | twitterapi_state_store / timeline_daily |
| 覆盖核验 | 每账号已覆盖区间、真实空窗口、截断/缺口 | 未覆盖不写成无新帖，不用导入时间冒充新鲜度 | twitterapi_timeline_coverage / ingestion_health |
| 原帖存储 | 平台 ID、作者、时间、原文、引用关系、内容哈希 | 冲突隔离，保留旧证据 | raw_posts / post_graph_memberships |
| AI 队列 | 输入版本、已付费回答、待处理/完成/延后、失败原因 | 跳过已保存解读；接口异常熔断；局部续跑 | ai_resume_queue / call_attribution_attempts / ai_usage_ledger |
| 汇总与发布 | 作者各时间窗观点、证据来源、构建源版本和线上哈希 | AI 失败不阻断原帖；保留旧摘要并标记滞后 | author_briefs / summaries / build-manifest |

## 接入一个新场景

1. 写场景配置：例如新增作者先确定历史起点、增量频率、是否含回复/引用/媒体，以及独立费用和结束条件。
2. 适配器输出统一原帖格式和覆盖证据；先用保存的样本测试分页、重复、空页、删帖、超长帖、引用作者和时间边界。
3. 小批真实采集验证后，进入统一缓存和覆盖表。新平台只替换适配器，不另建解读/发布链。
4. 原帖提交成功后入 AI 缺失队列。文本、图片、作者阶段回顾分别排队，图片读取失败不应伪造完整解读。
5. 监测四个独立指标：采集覆盖截止、待解读数量与最长等待时间、最近摘要时间、线上发布版本。任何一层卡住都能定位，不能仅展示总任务绿色。

## 尚未完成的长期配置

当前采集仅运行到 2026-11-22 08:10 UTC（北京时间 16:10），累计上限 30,000 credits。此次 AI 续跑处理已知缺失窗口，不自动创建无限期付费订阅。长期运行需要明确 provider 可持续额度，再把现有有限调度接入上述任务配置；禁止到期自动回退旧 Apify 产生双重费用。新场景没有经过上述小批验收前，不宣称可稳定全量覆盖。
